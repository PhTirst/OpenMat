# Function-handle compatibility with MATLAB R2022b

This record covers the clean-room differential cases accepted for OpenMat's
named and anonymous function-handle implementation. Each program observes only
its final `openmat_result`, and the MATLAB oracle normalizes failures to
OpenMat-owned categories without retaining proprietary diagnostic text.

## Accepted differential cases

| Case | Compatibility boundary |
| --- | --- |
| `function_handle_named_file` | `@name` resolves a function file from the configured source path and invokes it. |
| `function_handle_named_local` | A local function in the entry source takes precedence over a same-named function on the support path. |
| `function_handle_anonymous_multi_input` | Ordered anonymous parameters accept multiple inputs. |
| `function_handle_anonymous_capture` | Scalars and arrays are captured at handle construction; later workspace assignment and array mutation do not change the captured values. |
| `function_handle_anonymous_object_capture` | A captured value-class object is copied, while a captured handle-class object retains identity. |
| `function_handle_anonymous_multi_output` | A top-level call in an anonymous body forwards the caller's requested output count. |
| `function_handle_cell_call` | A named handle remains callable after cell storage and brace extraction. |
| `function_dynamic_invocation` | `feval` accepts char/string names and function handles, preserves multiple outputs, and dispatches named class methods from either a string name or lazy `@method` handle. `str2func` and `func2str` cover the matching named-handle conversions. |

All eight cases passed both the OpenMat conformance runner and a reference run
against the locally installed `$env:MATLAB_EXE`.
The checked-in JSON observations were generated by the oracle rather than
written by hand.

The accepted oracle selection can be regenerated from the repository root:

```powershell
pwsh -NoProfile -File tools/matlab-oracle/Invoke-MatlabOracle.ps1 `
    -MatlabPath $env:MATLAB_EXE `
    -Tag function-handle-r2022b `
    -ResultDirectory tests/conformance/reference/matlab-r2022b
```

The matching OpenMat selection is:

```powershell
pwsh -NoProfile -File tools/openmat-conformance/Invoke-OpenMatConformance.ps1 `
    -Case 'function_handle_*'
```

## Excluded unknown-target probe

An additional clean-room probe constructed and invoked a named handle for an
unresolvable target. OpenMat raised the specific kernel category
`runtime.unknownFunctionHandleTarget` (`OMR0018`), but the conformance CLI
currently normalizes that category to `other`. The R2022b oracle normalized the
probe's final failure to `undefined-name`.

Because the project-owned differential categories do not yet agree, this probe
is not an accepted manifest and no expectation was changed to hide the
difference. Accepting it requires the CLI normalization boundary to map
`runtime.unknownFunctionHandleTarget` to the agreed category; that code is
outside this corpus-only task.

## Deliberate non-claims

Anonymous `varargin` is covered separately by
`anonymous-varargin-r2022b.md`. This original corpus does not extend the
implementation boundary for statement-bodied anonymous functions,
class-constructor or script targets, multi-output member applications, or
handle lifetime across separate kernel requests. Those behaviors need their
own implementation and compatibility decisions before they can become
accepted differential cases.

OEX free functions already share the built-in registry path used by `feval`.
Dynamic native-method dispatch is verified separately with the checked-in C
OEX fixture because it has no MATLAB-side equivalent.
