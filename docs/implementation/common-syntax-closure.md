# Common syntax execution closure

This tranche closes seven frequently used MATLAB R2022b language paths through
the handwritten frontend, bytecode compiler, interpreter, Kernel source
linker, CLI conformance runner, and clean-room MATLAB oracle:

- `for` over ranges and matrix columns, including `break`, `continue`, and
  empty iteration;
- `switch` with one-time selector evaluation, first-match control flow,
  `otherwise`, and cell-valued case lists;
- named-function `varargin` and `varargout`, with actual `nargin` and
  caller-requested `nargout` metadata;
- nested functions with mutable shared lexical variables and closure lifetime
  beyond the parent frame;
- named `clear` in script/function workspaces and bare `clear` for ordinary
  script/function values.
- MATLAB command-form calls such as `hold on` and `grid off`, with arguments
  lowered as character text rather than workspace name expressions;
- the function-like `pi` constant in bare and parenthesized forms, including
  ordinary workspace shadowing.

## Bytecode v17 boundaries

Bytecode version 17 makes dynamic call and closure behavior explicit. A
`LoadVariadicInputs` prologue changes `parameter_count` from exact arity to the
minimum fixed arity and constructs a `1 x N` cell. `ReturnVariadic` expands only
the requested prefix of `varargout`. `MakeSharedClosure`, `LoadCapture`, and
`StoreCapture` distinguish MATLAB nested-function sharing from anonymous
function value capture. Shared storage is promoted lazily from an enclosing
local and remains owned by the registered closure after the parent returns.

Variable clearing uses separate global, local, and shared-capture instructions;
it never aliases function-local clearing to the interpreter workspace. Bare
script clearing has a Kernel test outside the observed MATLAB workspace because
an in-workspace oracle harness would clear its own observation state.

## Command form and function-like constants

Command form is represented by a dedicated lossless `CommandStmt` CST node and
an explicit HIR statement. It does not manufacture a `ParenApply` expression,
so ordinary `f(x)` remains unresolved between call and indexing. The compiler
loads the command callee through the normal dynamic name path, materializes each
argument as a UTF-16 character row, and emits the same statement-application
bytecode used by functional calls.

The R2022b probes establish these initial lexical boundaries: the first command
argument begins after horizontal space on the command's physical line; spaces
separate arguments; single quotes group text and remove their delimiters;
double quotes are retained character data and do not group embedded spaces;
`%` ends the command; `,` and `;` terminate it; and `...` may continue arguments
after the first argument. The parser retains all trivia and recovers an
unterminated single-quoted argument at the physical line boundary.

`pi` uses the runtime's opt-in bare-callable registry entry. An unresolved bare
load invokes it with zero inputs and one output, while `pi()` follows ordinary
application. Workspace values remain higher priority: after `pi = 7`, both
forms observe `7`; empty parenthesized application of an ordinary value is the
R2022b identity operation. Clearing that value exposes the built-in again.

## Measured corpus

The OpenMat-authored `common-syntax-r2022b` selection contains nine cases:
`for_range_control`, `for_matrix_columns`, `switch_selector_once`,
`switch_cell_case_list`, `function_variadic_arguments`,
`function_nested_closure`, `clear_workspace_and_locals`,
`syntax_command_form_common`, and `core_pi_resolution`. Their checked-in
references were generated by the installed MATLAB R2022b oracle. These cases
are samples, not a claim that every MATLAB syntax form is supported.

Remaining explicit boundaries include anonymous-function `varargin`, nested
functions inside `classdef` methods, `clear` patterns/function form, and
resource-unloading forms such as `clear all`, `clear classes`, `clear
functions`, and `clear mex`.

The generic command frontend also parses and compiles `box on`/`box off`, but
the current built-in registry has no `box` implementation. Closing that runtime
call requires adding `box_builtin` beside the other graphics state mutations in
`crates/openmat-builtins/src/graphics.rs` and registering it from
`register_graphics`; that shared graphics file is outside this tranche's edit
boundary.
